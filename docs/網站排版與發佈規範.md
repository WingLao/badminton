最後更新：2026-11-23（澳門時間）
適用：GitHub 儲存庫 `WingLao/badminton` 及其本機來源資料夾
本文件是「怎樣命名、怎樣排版、怎樣發佈」的固定做法。內容規則（學生／教練分眾、免費影片、羽毛球繁中例外與驗證等）仍以 `badminton/AGENTS.md` 和 `badminton/docs/網站維護規則.md` 為準；兩者衝突時，以使用者最新明確要求優先。

## 1. 命名與路徑（P23 起統一全部小寫）

### 1.1 網址格式

```text
https://winglao.github.io/badminton/<分類>/badminton-YYYY-MM-DD/
```

| 部分 | 規則 | 例子 |
|---|---|---|
| 儲存庫 | 固定 `badminton`（不可寫回早期錯字 `Badmionton`） | `WingLao/badminton` |
| 分類 | 英文小寫單字 | `learn`、`technology` |
| 期數資料夾 | `badminton-` ＋ 發佈日期（澳門時間 YYYY-MM-DD），全部小寫 | `badminton-2026-11-15` |
| 入口檔 | 每期資料夾一定有 `index.html` | `technology/badminton-2026-11-15/index.html` |

### 1.2 目前分類

| 分類 | 用途 | 本機來源資料夾 | 已發佈 |
|---|---|---|---|
| `learn/` | 羽球教學：YouTube 教學月報、學習精華、手指發力（F1–F3） | `教學/YouTube月報_YYYY-MM/`、`教學/手指發力/網站_YYYY-MM-DD/` | `learn/badminton-2026-11-15/`、`learn/badminton-2026-11-23/` |
| `technology/` | 面向教練的羽球科技：發球機、感測器、AI、器材、周邊 | `科技/` | `technology/badminton-2026-11-15/` |
| `research/` | 面向教練的研究筆記與文獻目錄（由程式自動轉換） | `學術/羽球研究筆記/`、`學術/近五年羽毛球文獻_2021-2026/文獻總目錄.csv` | `research/badminton-2026-11-23/` |
| `skills/` | AVANCO 後台兩個 skill 的說明（只介紹做法，不公開網址、帳號、密碼） | `AVANCO_html/.codex/skills/`（原檔不上傳） | `skills/badminton-2026-11-23/` |
| `updates/` | 每週更新紀錄（自動產生，不分期） | `tools/updates_log.json` | `updates/` |

新增分類：用一個英文小寫單字（例如 `equipment`、`tactics`），並同時建立 `<分類>/index.html` 分類目錄頁。

### 1.3 每期資料夾結構

```text
<分類>/
  index.html                 # 分類目錄：列出每一期，最新在最上面，底部「回首頁」
  badminton-YYYY-MM-DD/
    index.html               # 本期入口（主頁面）
    其他頁面.html             # 可選：完整版、核對表等，用中文檔名
    *.md                     # 可選：Markdown 文字版
    圖片/                     # 縮圖、圖表（本地保存，不熱連結）
    資料/                     # 可選：來源 JSON、核對紀錄
    assets/                  # 可選：共用 CSS / JS
```

### 1.4 每次發佈要同步的連結

1. 網站首頁 `index.html`：新增一張卡片，連到本期及分類目錄。
2. 分類目錄 `<分類>/index.html`：新增本期。
3. `README.md`：更新資料夾說明與線上連結。
4. 頁面內互相連結一律用**相對路徑**，例如 `../../learn/badminton-2026-11-15/…`。

## 2. 排版模式

### 2.1 頁面結構（由短到長，重點先行）

科技頁的主要讀者是教練：摘要協助快速判斷，完整比較與依據留作備查；學生頁才使用「小選手，大目標」與分步跟練。

參考：`technology/badminton-2026-11-15/`

| 次序 | 區塊 | 目的 |
|---|---|---|
| 0 | 頂部導覽列（可橫向滑動）＋深淺色切換 | 手機一指跳段落 |
| 1 | 標題區：一句主題＋3–4 個數字卡 | 5 秒知道這頁是甚麼 |
| 2 | **一分鐘重點**：5–7 句，關鍵字加螢光底 | 時間有限只看這段 |
| 3 | **先看哪支**：中文影片優先，再列有中文字幕／看畫面就懂的外語片 | 不懂英文也能選片 |
| 4 | 三分鐘看懂：6 張重點卡＋月份時間線 | 掌握全貌 |
| 5 | 關聯圖（SVG）＋比較表 | 看到彼此關係 |
| 6 | 分類影片卡片 | 逐支細看 |
| 7 | 教學／訓練應用表 | 連到實際使用 |
| 8 | 名詞小字典 | 查英文術語 |
| 9 | 影片索引表＋資料依據說明＋外部來源 | 查證與追溯 |

`learn/` 的學生頁另依 `docs/網站維護規則.md`：一次顯示一個細節、一句提示、練習與單項檢查。

### 2.2 影片卡片固定欄位

1. 縮圖（`圖片/<影片ID>.jpg`，YouTube `mqdefault`，連回 YouTube）＋右下片長＋左上代號（如 M1、A2）
2. 日期（澳門時間）· 頻道 · 觀看次數 · 依據標記
3. 中文標題（意譯，不只翻譯原標題）
4. 💡 一句話重點（螢光底）
5. 🔊 原音語言｜不懂英文友善度 ★–★★★｜👀 看片建議（哪一段、有無中文字幕）
6. 摘要＋3–5 個要點（有章節時間碼就列出）
7. 「適合：」誰用／甚麼場合

### 2.3 依據標記與可信度

| 標記 | 意思 |
|---|---|
| A | 有原始資料：論文、開源程式、詳細技術文章、可讀字幕 |
| B | 依影片簡介與發布者章節 |
| C | 只有標題或新聞簡介，細節待看片確認 |

- 時間碼只用字幕或發布者章節，**不自行編造**。
- 未取得字幕時，頁面要寫明「重點依簡介／章節整理，不是逐字稿」。
- 沒有方法說明的誇大宣稱（例如「3 週進步 60%」）要標示為行銷內容。

### 2.4 視覺規範

- 顏色只用 `:root` 色彩變數；深色模式用 `@media (prefers-color-scheme: dark)` 和 `[data-theme="dark"]` 兩處定義。
- 分類色固定：發球機／機器人＝藍、感測／AI＝紫、器材＝綠、周邊＝橙、主色＝墨綠、強調＝螢光黃綠。
- 字體：系統字＋`PingFang TC` / `Noto Sans TC`；內文 16px，行高 1.7。
- 單一 HTML 檔、CSS 內嵌；除縮圖外不依賴外部資源。
- p5.js 動畫（P35 起）：首頁頂部用「光藝術對打」3D 羽球場、各分類目錄頂部用「線框球場」，改編自使用者 `~/Desktop/P5js/fluid3d/bg_light_art`、`bg_mono_v2`。程式在 `assets/court.js`，p5.js 函式庫放本機 `assets/vendor/p5.min.js`（v1.11.1，LGPL-2.1），不連外部 CDN。內容頁不放動畫。畫面不在螢幕內或分頁在背景時暫停；系統「減少動態效果」時只畫靜態圖；沒有 WebGL 時只顯示漸層底。分類色：learn 150、technology 215、research 270、skills 25（HSB 色相）。

### 2.5 手機規範（兩類頁面都要易讀）

- Grid 一律寫 `minmax(min(XXXpx,100%),1fr)`，避免窄螢幕橫向溢出。
- **表格**：加 `class="cards"`；640px 以下自動變成一行一張卡片，每格前顯示欄名（由頁尾小段 JS 從表頭產生 `data-label`）。
- **關聯圖 SVG**：640px 以下隱藏，改顯示由上而下的 HTML 流程方塊（`.flow`），字體正常大小。
- 導覽列可橫向滑動；按鈕和連結夠大、易按。
- 發佈前截圖檢查：320、360、390、430px 手機，以及 768、1280px。

## 3. 內容規範（摘要）

- 繁體中文為主；使用者英文不好、時間有限 → 每支影片都要有中文一句話重點，外語片標明原音及看片建議，並附「開自動翻譯中文字幕」步驟。
- 羽毛球文件依最新例外只需繁體中文，只做中文學生可懂性測試；英文測試不適用。學生頁另做跟練走查，科技頁採教練應用語氣。
- 推薦給學生的影片須核實可免費公開播放（未登入播放器狀態）；產品可能收費，要註明學生不需購買。
- 只收錄指定年份發布的影片；較早影片要標明年份。
- 保留影片原連結與本地縮圖，不下載影片本體。

## 4. 發佈步驟

操作前提：由有本儲存庫寫入權限的維護者操作；已安裝 Git（版本紀錄工具）、Python 3（執行檢查程式的工具），並已登入 GitHub。終端機是輸入下列指令的視窗，目前位置應為本機的 `badminton` 儲存庫。學生閱讀網站不需要這些權限。

1. 輸入 `git status --short`。預期看到本次修改清單；`M` 代表已修改，`??` 代表新增。保留其他人的修改。
2. 把本次成品同步到相應的 `<分類>/badminton-YYYY-MM-DD/`。預期主頁為 `index.html`，圖片及必要資料在同一期資料夾。
3. 更新網站首頁 `index.html`。預期入口指向正確分類及本期網址。
4. 更新本次分類的 `index.html`。預期最新一期列在前面。
5. 更新 `README.md`。預期資料夾與公開網址符合本次版本。
6. 輸入 `python3 tools/check_site.py`。預期顯示「檢查通過」；這會檢查檔案連結、精確大小寫與既有影片權限紀錄，不會即時重查影片或產品資料。
7. 用瀏覽器檢查手機及桌面版面。預期文字、圖表及按鈕可閱讀操作，沒有橫向溢出。
8. 輸入 `git diff --check`。預期沒有錯誤輸出。
9. 用 `git add` 加入本次相關檔案。例如只改規則檔時輸入 `git add AGENTS.md docs/`；不要加入其他人的未完成修改。
10. 用 `git commit -m "具體修改說明"` 記錄本次版本。把說明文字換成本次修改內容；預期看到新的版本編號。
11. 輸入 `git pull --rebase origin main` 同步遠端修改。預期同步成功；若有衝突，維護者先保留雙方內容並解決，不能直接覆蓋。
12. 輸入 `git push origin main`。預期成功推送 `main`；不可強制推送。
13. 在 GitHub 儲存庫開啟 `Actions`（自動工作流程），等待本次 `pages-build-deployment` 成功。預期出現綠色成功標記。
14. 核對線上網址及圖片。預期可開啟，且線上檔案內容與本機本次版本一致。
15. 在預設瀏覽器開啟已確認的 HTTPS 網址。預期顯示學生學習頁或教練科技頁，讀者定位正確。

本機來源與儲存庫副本保持同步。之後若先在儲存庫修訂頁面，要把完成版本同步回本機來源。

## 5. 每週自動更新（P28 起）

每星期六早上 8 點（澳門時間）自動執行 `bash tools/weekly_update.sh`。這支程式依次做：

1. 先確認儲存庫沒有未提交的修改；有的話停止，避免覆蓋別人的工作。
2. `git pull --rebase origin main` 同步遠端。
3. `python3 tools/build_site.py`：
   - 研究筆記或文獻目錄有變動 → 新增一期 `research/badminton-YYYY-MM-DD/`；沒變動就不新增。
   - `科技/2026羽球科技速覽.html`、各期學生頁的本機來源有修改 → 同步到網站副本。
   - 發現新的 `教學/YouTube月報_*` 或 skill 原檔有修改 → 只寫入「待整理」，不自動發佈（學生影片必須先人工核對可免費觀看）。
   - 重建首頁、各分類目錄與 `updates/`。
4. `python3 tools/check_site.py` 與 `git diff --check`。
5. 提交、推送，等待 GitHub Pages 成功，再用 curl 核對 6 個線上網址回應 200、更新紀錄顯示當天日期。

紀錄存在本機 `網站維護/自動更新紀錄/更新_YYYY-MM-DD.log`。分類設定與每期標題在 `tools/site_config.json`；手寫的學生頁、工具說明頁不會被程式覆寫，只會重建目錄。

## 6. 四欄筆記、年級標示與搜尋引擎（P39–P40 起，取代 P36 的閱讀卡）

- 〈閱讀與記憶工作流〉是**整理文章時的方法**：每整理一篇文章，就依範本（Core Thesis／Key Metrics 最多 3 項附數值、基準、出處／Logic Flow 標「相關」「機制未明」／Cross-Domain Link 標「待驗證」，加閉卷回想）寫一份四欄筆記**交給使用者**，存放在 `~/Desktop/Badminton/網站資料/四欄筆記_YYYYMMDD/`。**網站不顯示閱讀卡，也沒有「閱讀方法」頁。**
- 網站不顯示「國一至國三」等年級標示；學生分類對外稱「學生學習／小選手」。內容仍以初中程度撰寫。
- 全站每頁加 `<meta name="robots" content="noindex, nofollow, noarchive">`，不讓搜尋引擎收錄（GitHub Pages 專案網站的 robots.txt 不會生效）。`build_site.py` 的 `tidy_hand_pages()` 會替手寫與舊頁面自動補上。
- 學術資料夾的研究文件（`.md`）與鄭任佑的比賽 Excel 都放進 `research/`；論文 PDF 不上傳，只列題名與原出處（P40 使用者選擇）。
